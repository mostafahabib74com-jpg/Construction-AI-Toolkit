# Compliance matrix

## Objective

Create a complete, atomic, source-linked requirements matrix that drives all tender responses and final compliance review.

## Required inputs

- Controlled current tender package and addenda.
- Evaluation criteria and scoring rules.
- Submission instructions, forms, portal fields, and contract schedules.
- Approved document taxonomy and responsibility model.

## Procedure

1. Extract requirements from every relevant source, including tables, notes, forms, drawings, schedules, and portal instructions.
2. Split compound clauses into atomic requirements while preserving parent and duplicate-source relationships.
3. Record requirement ID, text, summary, source locator, category, mandatory/scored status, weight, deliverable, owner, contributors, due date, response location, evidence, and review route.
4. Classify response state using the controlled compliance states; never equate drafted text with compliance.
5. Map requirements to proposal sections, forms, domain artifacts, assumptions, exclusions, qualifications, deviations, and queries.
6. Identify contradictions, vague requirements, missing owners, missing evidence, overdue responses, and mandatory noncompliance.
7. Reconcile all changes from addenda and client answers, retaining superseded requirement history.
8. Produce summary metrics with deterministic counts and no hidden omissions.

## Deliverables

- Detailed compliance matrix.
- Mandatory and scored requirement dashboard specification.
- Responsibility and contribution matrix.
- Evidence and response cross-reference.
- Noncompliance, deviation, gap, and overdue-action report.
- Addendum impact reconciliation.

## Completion gates

Final compliance requires approved responses and evidence for all applicable mandatory requirements plus Tender Manager and discipline-owner review.
