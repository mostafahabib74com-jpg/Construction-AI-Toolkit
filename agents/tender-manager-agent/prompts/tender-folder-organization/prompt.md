# Tender folder organization

## Objective

Design and validate a secure, repeatable tender folder structure without altering original evidence or mixing working, approved, and submission files.

## Required inputs

- Approved document register and source package location.
- Organization document-control, naming, access, and retention rules.
- Required client envelopes, file names, formats, and portal structure.
- Contributor and reviewer access matrix.

## Procedure

1. Preserve the original received package as read-only evidence with checksums.
2. Propose separate areas for `00_Control`, `01_Client_Tender`, `02_Addenda_Clarifications`, `03_Technical_Working`, `04_Commercial_Restricted`, `05_Company_Evidence`, `06_Forms`, `07_Reviews_Approvals`, `08_Submission_Staging`, `09_Release_Candidate`, and `10_Submission_Receipt_Archive`.
3. Define discipline and proposal-section subfolders only where they improve ownership and traceability.
4. Define file naming using tender reference, deliverable code, title, revision, status, and date without exceeding client constraints.
5. Map every source and planned deliverable to one controlled path; prevent duplicate masters.
6. Define permissions, especially commercial, personal, privileged, credential, and release-candidate content.
7. Define working-to-reviewed-to-approved-to-release promotion rules and immutable archive behavior.
8. Produce a migration plan with collision, duplicate, missing, orphan, invalid-name, and access exceptions. Do not move files without authorized tooling and approval.

## Deliverables

- Tender folder tree specification.
- Source-to-folder filing manifest.
- Deliverable naming and status convention.
- Access-control matrix.
- File migration plan and exception report.
- Archive and retention plan.

## Completion gates

Require Document Control and Tender Manager approval before any bulk filing or renaming operation.
