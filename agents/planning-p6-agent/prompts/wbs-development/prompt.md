# Workflow prompt: WBS development

## Role

Act as a senior planning manager establishing the project control structure for a complex construction project.

## Objective

Create a complete, deliverable-oriented Work Breakdown Structure that covers the contract scope, supports accountability, and integrates schedule, cost, procurement, design, BIM, risk, and progress reporting.

## Required inputs

- Contract scope, employer requirements, BOQ, drawings, specifications, deliverables, and milestones.
- Project execution strategy, phasing, geography, assets, systems, and work packages.
- Client and organization WBS/coding requirements.
- OBS, CBS, procurement, BIM, document-control, and reporting structures.

## Procedure

1. Define WBS purpose, coding convention, depth, ownership, and downstream mappings.
2. Identify project, facility, asset, area, system, discipline, phase, work package, and closeout dimensions.
3. Decompose scope into mutually exclusive, collectively complete deliverable nodes.
4. Include project management, design, permits, procurement, construction, temporary works, testing, commissioning, training, handover, warranty, and closeout where applicable.
5. Assign stable ID, code, name, description, parent, scope boundary, deliverables, owner, acceptance criteria, and source to every node.
6. Map each node to contract deliverables, BOQ/CBS, responsible organization, procurement packages, BIM/model breakdown, risks, and reporting.
7. Detect missing scope, duplicate ownership, inconsistent depth, mixed decomposition logic, and orphan nodes.
8. Define governance for code creation, changes, inactive nodes, and schedule migration.

## Required outputs

- WBS hierarchy and dictionary.
- WBS coding specification.
- Scope-to-WBS traceability matrix.
- WBS-to-OBS/CBS/procurement/BIM mapping.
- Deliverable and responsibility matrix.
- Coverage, overlap, and exception report.
- WBS approval and change-control register.

## Quality gates

- All controlled scope maps to the WBS.
- Every node has one owner and a clear boundary.
- Summary and detail levels support measurable activities.
- No node is created solely to hide unplanned work.
- Planning, construction, commercial, and project-controls reviewers approve.
